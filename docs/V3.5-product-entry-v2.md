# Lens Diary V3.5 迭代说明
## 商品信息录入 V2

**版本目标：** 降低美瞳档案录入成本，提高商品截图识别失败时的可用性，并修正品牌/购买渠道的数据结构。  
**版本来源：** 第一轮真实用户测试反馈  
**上一版本：** V3.4  
**计划版本：** V3.5

---

## 1. 背景

Lens Diary 当前的核心使用链路之一是：

> 上传商品截图 → 自动提取品牌 / 产品名 / 参数 → 用户确认 → 保存美瞳档案

第一轮用户测试后，商品录入流程集中暴露出 3 个问题：

1. 商品截图信息提取存在失败情况；
2. “视客”被当作品牌，但实际属于购买渠道/销售平台；
3. 当前品牌选项覆盖不足。

三个问题本质上都指向同一模块：**商品信息录入的数据结构与容错能力不足。**

因此 V3.5 不继续零散增加品牌或单独修补某一个 OCR Case，而是统一升级为 **“商品信息录入 V2”**。

---

## 2. 用户反馈与问题定义

### P0｜图片提取信息失败

**用户现象：**  
上传商品截图后，部分商品参数无法正确识别，导致自动录入失败或需要重新手动填写。

**问题本质：**  
当前流程过度依赖 OCR 一次性完整识别。当部分字段识别失败时，用户容易感知为“整个识别功能失败”。

**产品判断：**  
截图识别的价值不是追求每次 100% 自动填写，而是尽可能减少用户手工录入量。

**V3.5 处理：**
- 改为“字段级识别”，识别成功的字段正常填入；
- 未识别字段保持为空，由用户补充；
- 不因单个字段失败而判定整个识别流程失败；
- 保留原始 OCR 文本，方便用户和后续调试核对；
- 所有自动填写结果在保存前均允许用户修改。

---

### P1｜品牌与购买渠道概念混淆

**用户反馈：**  
“视客”是一个购买美瞳的网站，而不是美瞳品牌。

**问题本质：**  
当前数据模型把“品牌”和“购买渠道”混为一个字段。

**V3.5 数据结构调整：**

原结构：
- 品牌
- 产品名称
- 产品参数

调整为：
- **品牌 Brand**
- **产品名称 Product Name**
- **购买渠道 Purchase Channel**
- 产品参数

示例：
- 品牌：OLENS
- 产品名称：Big Glowy Gray
- 购买渠道：视客

**渠道示例：**  
视客、淘宝、天猫、京东、品牌官方渠道、线下门店、其他。

购买渠道不是必填字段，用户可自行输入。

---

### P1｜品牌覆盖不足

**用户现象：**  
当前可选品牌数量有限，用户使用的品牌不一定存在于列表中。

**问题本质：**  
品牌本身是一个持续变化的开放集合，不适合使用完全封闭的枚举列表维护。

**V3.5 处理：**
品牌输入改为：

> 常见品牌快捷选择 + 搜索/输入 + 自定义品牌 + 最近使用品牌

具体逻辑：
- 用户可以选择已有常见品牌；
- 用户可以直接输入任意新品牌；
- OCR 识别到品牌库之外的品牌时，也允许直接填入；
- 成功保存过的自定义品牌进入“最近使用”；
- 不再通过不断扩大硬编码品牌列表解决覆盖问题。

---

## 3. V3.5 新的商品录入流程

### 当前流程

> 上传商品截图  
> → OCR  
> → 匹配现有字段/品牌  
> → 成功或失败  
> → 保存

### V3.5 流程

> 上传商品截图  
> → OCR 尽可能识别信息  
> → 将识别结果分别映射到各字段  
> → 未识别字段留空  
> → 用户检查 / 修改  
> → 品牌支持任意输入  
> → 品牌与购买渠道分别记录  
> → 保存档案

核心原则：

> **识别失败 ≠ 录入失败。**

OCR 是帮助用户减少输入，不是替用户做不可修改的最终判断。

---

## 4. 字段设计

| 字段 | 是否必填 | 输入方式 |
|---|---|---|
| 品牌 | 否 | 常见品牌 / 搜索 / 自定义输入 |
| 产品名称 | 否 | 文本输入 / OCR |
| 购买渠道 | 否 | 常见渠道 / 自定义输入 |
| 颜色 | 否 | 选择 / 自定义 |
| DIA | 否 | OCR / 选择 / 手动 |
| G.DIA | 否 | OCR / 选择 / 手动 |
| BC | 否 | OCR / 手动 |
| 含水量 | 否 | OCR / 选择 / 手动 |
| 周期 | 否 | OCR / 选择 |
| 锁边 | 否 | 选择 / 自定义 |

现有评分、舒适度、照片、备注等字段保持不变。

---

## 5. OCR 容错规则

V3.5 继续使用当前浏览器端 OCR 方案，不在本版本强行接入新的 AI 服务。

识别优先级：
1. 中文/英文字段标签；
2. 数值合理范围；
3. 参数之间的物理关系；
4. 用户最终确认。

例如：
- BC：约 8.0–9.2 mm；
- DIA / G.DIA：通常处于合理镜片直径范围；
- 一般 DIA ≥ G.DIA；
- 含水量按照合理百分比范围判断。

若不能可靠确定字段：

> **留空，不猜。**

后续版本可评估：

> 商品截图 → 多模态视觉模型 → 结构化 JSON → 领域规则校验 → 用户确认

但不属于 V3.5 必须范围。

---

## 6. 本版本不做

为了控制 MVP 迭代范围，V3.5 暂不加入：
- 用户账号系统；
- 云数据库；
- 多设备同步；
- 真实联网社区；
- 商品数据库；
- 淘宝/视客链接直接抓取；
- 新的付费 AI API；
- 自动购买推荐。

---

## 7. 验收标准

### 截图录入
- 截图只识别出部分参数时，用户仍可以继续创建档案；
- 单个字段识别失败不会导致整个页面报错或中止；
- 用户能看到并修改 OCR 自动填写的结果。

### 品牌
- 用户可以输入列表外的任意品牌；
- 自定义品牌可以正常保存；
- 最近成功使用过的品牌能够再次快速选择。

### 购买渠道
- “视客”不再作为品牌出现；
- 页面存在独立“购买渠道”字段；
- 用户可以选择或输入视客、淘宝、天猫、线下门店等渠道；
- 渠道为空也可以保存。

### 数据兼容
- V3.4 已保存的本地 Lens Diary 档案不能因为 V3.5 更新而丢失；
- 老数据没有 purchaseChannel 字段时，应兼容为空值。

---

## 8. 版本价值

本次更新不是简单增加几个品牌，而是根据第一轮真实用户反馈，对商品录入模块做结构性调整：

> **封闭品牌枚举 → 开放品牌输入**  
> **品牌/渠道混合 → 数据结构分离**  
> **OCR 完整成功 → 字段级容错**

这使 Lens Diary 的录入流程更适合真实、不断变化的美瞳商品环境。

---

## 9. 后续验证

V3.5 上线后，第二轮测试重点观察：
1. 用户能否理解“品牌”和“购买渠道”的区别；
2. 自定义品牌是否比原品牌下拉框更顺畅；
3. OCR 部分成功时，用户是否仍觉得它节省时间；
4. 用户手动补全一个商品档案需要多久；
5. 是否仍出现新的商品字段或录入需求。

---

**产品原则：**

> Lens Diary 的目标不是让用户记录得更多，而是让值得留下的真实佩戴经历更容易被记录和重新找到。
